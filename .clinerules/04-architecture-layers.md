# Архитектура: Layer First

Основные слои:

- Repository — работа с БД, только запросы.
- Service — бизнес-логика.
- Controller — только HTTP (парсинг запроса, вызов сервиса, возврат ответа через Resource).

Правила разделения ответственности:

- Бизнес-логика располагается только в Service.
- Repository не содержит бизнес-логику, только доступ к данным.
- Controller не содержит бизнес-логику и не формирует SQL/запросы.

Используется версионирование API (`src/http/v1`, `src/routes/v1`). Новые endpoint'ы размещаются только внутри соответствующей версии, не вне структуры versioned API.

## Простые и сложные сущности

Для простых CRUD-сущностей отдельный слой `domain` не создаётся.

Примеры простых сущностей: `category`, `brand`, `attribute` и другие, где логика ограничивается CRUD, slug, soft delete и валидацией.

Для таких сущностей — стандартная цепочка: **Repository → Service → Controller**.

Слой `domain` создаётся только для сложных бизнес-сущностей с самостоятельными бизнес-правилами, инвариантами, расчётами, состояниями или сценариями взаимодействия.

Примеры сложных сущностей: `cart`, `order`, `payment`, `inventory`.

Если сущность не содержит сложной бизнес-логики — не создавай для неё `domain`, даже если пользователь не указал это явно. При сомнении — уточни.

## Структура директорий

- `src/boot` — инфраструктура (абстрактные классы, контейнеры, логирование, миксины, общие типы, утилиты). Бизнес-код сюда не помещается.
- `src/database` — миграции и сиды.
- `src/http` — контроллеры, requests, resources, filters, request-queries.
- `src/repositories` — репозитории предметной области.
- `src/services` — сервисы предметной области. Инфраструктурный код сюда не помещается.
- `src/routes` — маршруты Express.
- `src/middlewares` — middleware.
- `src/views` — SQL View и связанные типы.
- `src/types` — типы прикладного уровня.

Перед созданием нового файла — проверь, нет ли уже подходящего места в существующей структуре (см. `08-workflow-checklist.md`).
