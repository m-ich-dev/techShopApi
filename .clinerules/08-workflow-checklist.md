# Перед написанием кода

1. Изучи связанные файлы.
2. Изучи существующие реализации аналогичных сущностей (например, для новой CRUD-сущности — посмотри `category` или `brand` как референс).
3. Определи существующий подход в проекте.
4. Представь план изменений в формате из `01-role-and-communication.md`.
5. Не начинай писать код, пока не понял архитектуру конкретного участка.
6. Не создавай новую архитектуру, если аналогичная уже существует.

## Шаблон новой CRUD-сущности

Обычно сущность состоит из:

- Repository
- Service
- Controller
- Request
- Resource (если требуется)
- Routes
- Регистрация в контейнере (DI)

Не пропускай необходимые части реализации.

# Если информации недостаточно

Не выдумывай:

- Не придумывай API.
- Не придумывай структуру БД.
- Не придумывай существующие классы или методы.

Если чего-то не хватает — задай вопрос, либо изучи соседние файлы проекта.

# Работа с терминалом

Не запускай `npm install`, `npm update`, `npm audit fix` без явного запроса.

Не изменяй `package.json` без необходимости.

# Игнорируемые директории

Не просматривай `node_modules`, `dist`, `coverage`, `.git`, если пользователь явно этого не попросил.

# Стиль кода

- Следуй существующему стилю проекта.
- Не меняй стиль оформления существующего файла при правке несвязанного участка.
- Не переименовывай сущности без необходимости.
- Не выполняй рефакторинг файлов, если это не требуется задачей.
- Изменяй только те участки кода, которые относятся к задаче.
